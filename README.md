# 군산시탁구협회 디지털 행정 시스템

> 반복되는 회원등록·이적·승인·문서 취합 업무를 하나의 디지털 행정 흐름으로 재설계한 프로젝트입니다.

- Live: https://gunsan-table-tennis-association.vercel.app
- Case Study: https://studio.dechive.dev/work/association-system/
- Stack: Next.js · TypeScript · Supabase · ExcelJS · js-hwp · Vercel

---

## Why

문제는 Excel이나 HWP 자체가 아니었습니다.

군산시탁구협회의 회원등록은 정기적으로 반복되고, 각 동호회가 양식을 내려받아 작성한 뒤 협회 임원진에게 전달합니다. 협회는 여러 파일을 다시 모아 누락과 최신본을 확인하고, 상위 기관 제출 형식에 맞게 재정리해야 합니다.

이적 업무도 신청서 작성, 승인 주체 확인, 서명, 협회 전달처럼 사람이 문서를 계속 옮겨야 했습니다.

이 프로젝트의 목표는 **최종 제출 형식을 없애는 것**이 아니라, 그 문서를 만들기 전까지 반복되던 **전달·취합·재입력·상태 확인을 줄이는 것**이었습니다.

---

## PM / Product Approach

기존 회원등록 업무를 다음 6단계로 나눠 병목을 확인했습니다.

1. 양식 다운로드
2. 동호회별 작성
3. 협회 임원진에게 전달
4. 여러 파일 취합
5. 누락·최신본 확인
6. 제출 양식 재정리

그 뒤 MVP 범위를 아래 4개 핵심 업무로 제한했습니다.

- 회원등록
- 이적 승인
- 문서 생성
- 외부 대회정보 확인

사람이 해야 하는 승인과 판단은 남기고, 사람이 굳이 파일을 전달해야 하는 과정만 줄이는 방향으로 설계했습니다.

## What It Does

### 회원등록
- 회원등록 명단 작성 및 제출
- 신청 상태 관리
- 협회 임원진의 제출 명단 확인
- 희망부 관련 알림

### 이적 승인
- 이적 신청
- 승인 대상별 상태 추적
- 협회 승인 대기/완료 상태 관리

### 문서 출력
- 협회가 필요한 시점에 Excel/HWP 문서 생성
- 상위 기관이 요구하는 기존 제출 형식은 유지

### 게시·운영
- 공지사항
- 자유게시판
- 조직도
- 동호인리그 / 디비전리그
- 대회일정
- 관리자 알림

---

## Architecture

- **Next.js / TypeScript** — 웹 애플리케이션
- **Supabase / PostgreSQL** — 회원, 게시물, 등록명단, 승인, 알림 데이터
- **ExcelJS / js-hwp** — 기존 행정 문서 형식 출력
- **Vercel** — 배포

서버 권한이 필요한 값과 관리자 인증 정보는 브라우저에 노출하지 않고 서버 환경변수로 관리합니다.

---

## Product Principle

> 디지털 전환은 모든 기존 방식을 없애는 일이 아니라,  
> 사람이 굳이 할 필요 없는 전달과 반복을 줄이는 일이라고 생각합니다.
